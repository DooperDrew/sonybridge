# Lessons Learned

Living log of things that went wrong or surprisingly right, and the rule they produced.
Generic lessons (not tied to this project) are tagged **[KIT]** and get promoted into the
`project-kickstart` plugin during the retrospective.

| Date | Context (task / conversation) | What happened | Rule / fix adopted | Scope |
|---|---|---|---|---|
| 2026-10-31 | CLI & Tray Unification | Users had to use a separate CLI binary to test Bluetooth/Audio probe while app ran as detached GUI | Unified CLI argument dispatch (sonybridge-app probe / --enforce-a2dp) with AttachConsole and dynamic tray telemetry updates | project |
| 2026-10-31 | packaging | Releasing multiple executables in the distribution bundle confused users | Single standalone setup executable (SonyBridge-Setup.exe) and clean single-binary portable zip | [KIT ✓] |
| 2026-10-31 | UX & In-App Maintenance | Users had no way inside the GUI to re-run setup, create shortcuts, or trigger uninstallation | Added in-app maintenance buttons in Windows tab and progressive Setup Wizard / Uninstaller | [KIT ✓] |
| 2026-10-27 | Autonomous UI & A11y QA via `ui-qa-tester` (Tauri / WebView2) | Tauri/WebView2 apps delay accessibility tree hydration until initial query, nest DOM elements under `Chrome_RenderWidgetHostHWND` child HWNDs, and ignore mouse clicks sent to the top-level outer frame | Test actuators must walk child HWND trees (depth >= 15-20), warm up UIA with a brief 300ms pause, convert mouse coordinates to child client coordinates via `ScreenToClient(render_hwnd)`, and calculate contrast on small labels using the 99th luminance percentile | [KIT] |
| 2026-10-25 | Documentation Parity for Multi-Channel Install & Setup Wizard | After adding WinGet/Scoop manifests and setup scripts (`setup-wizard.ps1`, `install.ps1`, `uninstall.ps1`), `docs/user-guide.md` still had the old M0 `target\release\` instructions and `README.md` omitted WinGet/Scoop commands and `-Silent`/`-NoGui` wizard options | Whenever adding or evolving packaging/distribution scripts (`package-release.ps1`, `setup-wizard.ps1`, `install.ps1`, `uninstall.ps1`, `generate-manifests.ps1`), immediately synchronize `README.md`, `docs/user-guide.md`, `docs/02-requirements.md`, `docs/08-community-and-growth-strategy.md`, and `docs/release-methodology.md` with all 4 installation channels (WinGet, Scoop, Guided Setup Wizard, Portable ZIP) and uninstallation steps, then re-run `package-release.ps1` so the `.zip` on GitHub Releases includes the updated docs and scripts | [KIT] |
| 2026-10-25 | Centralized Template Sync (`DooperDrew/project-template`) | `sonybridge` and local `project-kickstart` templates lacked the latest GitHub Copilot Cloud Agent workflow (`agent_task.yml`, `agent_task.md`, full `copilot-instructions.md`, `docs/README.md`, and canonical `multi-agent-methodology.md`), and capturing `gh api` raw stdout in PowerShell 5.1 without `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` mangled non-ASCII symbols | Keep `.github/copilot-instructions.md`, `.github/ISSUE_TEMPLATE/agent_task.yml`, `.github/pull_request_template.md`, `AGENTS.md`, `CONTRIBUTING.md`, `docs/README.md`, and `docs/multi-agent-methodology.md` synchronized with `DooperDrew/project-template`; set `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` when capturing external CLI stdout in PowerShell 5.1 | [KIT] |
| 2026-10-25 | M6 / GitHub Governance & Packaging | User noted that `.exe` binaries were only in local `target/release/` (gitignored) and that milestones/issues/releases were not created on GitHub | Always create GitHub Milestones and Issues for every roadmap milestone (`M0`..`Mn`), build a portable `.zip` release bundle via `scripts/package-release.ps1` (including `setup-wizard.ps1`, `install.ps1`, `uninstall.ps1`), and publish it to GitHub Releases (`gh release create`) even while physical hardware QA is `Pending` | [KIT] |
| 2026-10-25 | PowerShell `gh api` Pipeline | Piping `gh api` output directly into a static .NET method call (`\| [System.Text.Encoding]::UTF8.GetString($input)`) caused PowerShell to hang on pipeline binding | Never pipe directly into a static .NET method call in PowerShell; use `gh api -H "Accept: application/vnd.github.raw"` or assign output to a variable first | [KIT] |
| 2026-10-25 | M0.4 Audio Endpoint COM Integration | Windows COM interface pointers (e.g. IMMDeviceEnumerator) drop after `CoUninitialize()` if in outer scope, causing STATUS_ACCESS_VIOLATION | Explicitly scope COM objects in an inner block so RAII drops interfaces before `CoUninitialize()`, and free PWSTR via `CoTaskMemFree` | [KIT] |
| 2026-10-25 | Project Setup (Kickstart) | Windows Bluetooth RFCOMM services may be locked or require explicit permissions when opened via WinRT if already connected as audio | Always design transport with a fallback to Winsock `AF_BTH` socket and verify via M0 spike before writing application logic | project |
| 2026-10-25 | Project Setup (Kickstart) | PowerShell 5 defaults to UTF-16/ANSI encoding when redirecting output | Always use dedicated file writing tools or `Set-Content -Encoding utf8` in PowerShell | [KIT] |
| 2026-10-25 | Project Setup (Kickstart) | Windows only permits one process to own a tray icon or single-instance named pipe mutex | Automated tests must use unique identifiers and timeout protection | [KIT] |
